# v0.6 bulk content production queue (WO-19 Phase 6)

Prepared, not authored. No mission content in this document has been written into
`src/modules`; this is the planning input for the next content-authoring sprint. Root types are
drawn from the closed set in `scripts/lib/rootType.ts` (しくみ／めあて／わかれ). Gold exemplars:

## Story Missions 1-4 through 1-8

### 1-4 — 遠足のおやつ300円「バナナはおやつに入りますか？」

- **Root type:** しくみ — a category-boundary mechanism (what counts as "おやつ" under the
  300-yen field-trip rule and why), not a single moral purpose.
- **Intended questioning tension:** the classic real Japanese school convention that a whole
  banana is a genuinely disputed edge case for a "300円までのおやつ" rule. The child moves from
  "is a banana a snack, yes/no" toward noticing the rule's *wording* doesn't cleanly capture its
  *purpose* — a category needs a boundary, and boundaries have edge cases.
- **Likely move coverage:** naze (why doesn't whole fruit obviously count) → tsumari (so what
  does "おやつ" actually mean here) → hokaniwa (are there other disputed edge cases). First
  mission combining three of the four moves in one chain.
- **Required human gates:** Gate 1 (the banana/300-yen convention is a well-documented real
  practice — practice-type claim, hedged as "commonly" per the WO-13 guardrail, never asserted as
  universal school policy) and Gate 2.
- **Dependencies:** first mission to exercise the FULL 4-slot assembly (what/why/who/format
  together, per the old spec table's "full 4-slot build"). Verified structurally ready — no
  engine change needed: `resolver.ts`'s `resolveArchetype` already iterates `rule.when` generically
  over any slot set, and `SlotAssembly.tsx` already renders `phase.slots.map(...)` generically.
  Recommend a smoke test alongside authoring, not before it.

### 1-5 — 「みんなやってる」の「みんな」

- **Root type:** わかれ — a distinction/differentiation type: "みんな" almost never means
  literally everyone; the root should land on separating the vague quantifier from the actual
  (usually small) group being referenced.
- **Intended questioning tension:** the child probes a claim like 「みんなスマホ持ってるよ」 to
  discover "みんな" usually means "a few specific people I have in mind," not a literal universal
  claim.
- **Likely move coverage:** tsumari (what does "everyone" actually mean here) → hokaniwa (is
  there anyone who does NOT do it) → naze (why do people say "everyone" when they mean a few).
- **Recommended pairing:** this is the natural first real home for the Perspective-shift
  prototype built in WO-19 Phase 3C (`Mission.perspective`) — a second voice stating who they'd
  actually include in "みんな" is a clean, non-debate way to make the vague-quantifier point land.
  Not mandatory; flagged as the best-fit candidate, not a requirement.
- **Required human gates:** Gate 1 (any claim here must stay in "commonly used loosely to mean a
  smaller group" territory, never asserting a specific real number/statistic) and Gate 2.
- **Dependencies:** none beyond Package 2's own authoring; ひみつ (trap) cards are listed in the
  old spec table's co-play column starting here, but no `DigTag` value for a "trap" exists in the
  engine (`DigTag = 'deepen' | 'sideways' | 'repeat' | 'offtopic'`) — ひみつ appears only as a
  PRINT-DECK card kind (`cardTypes.himitsu`), never as an in-app Dig mechanic. If "traps begin"
  is meant as an in-app mechanic (not just a physical card-game concept), that is new engine
  scope requiring a Founder/architecture decision, not something to build unilaterally in a
  content-authoring WO.

### 1-6 — 「ずるい」ってなに？

- **Root type:** しくみ — fairness as a relational/structural concept (a shared expectation
  someone broke), not "whatever I personally dislike."
- **Intended questioning tension:** the child compares several situations called 「ずるい」 to
  discover the common thread is a broken shared rule/expectation, not simply "something
  unwelcome happened to me."
- **Likely move coverage:** hokaniwa (primary, per the old spec table) → naze → tsumari.
- **Required human gates:** Gate 1, Gate 2.
- **Dependencies:** none — reuses the existing おうちトーク wrapper screen for its co-play beat
  (already implemented, no new mechanism needed).

### 1-7 — 「かして」と言われたら、かさなきゃいけない？

- **Root type:** めあて — the purpose behind sharing norms is social reciprocity/consent, not an
  absolute obligation.
- **Intended questioning tension:** naive "must always lend if asked" vs. noticing that lending
  is conditioned on context, relationship, and genuine willingness — the root lands on lending as
  a social exchange, not a blind duty.
- **Likely move coverage:** all four moves plausibly relevant; the old spec table's own framing —
  「どのカードで掘る？」 (the CHILD chooses which move fits the situation) — is the point of this
  mission, not incidental.
- **Required human gates:** Gate 1 (careful hedging — must not frame either "always lend" or
  "never lend" as correct), Gate 2.
- **Dependencies — real blocker, not authoring work:** "the child chooses which move" implies
  more than one valid `deepen` card in a single hand. `pipeline/04_lint.ts` currently hard-enforces
  exactly one `deepen` card per Dig layer as part of the v0.6 content contract — this is a
  genuine open design question (see Package 1's "remaining requirements"), not something a
  content-authoring WO should resolve unilaterally by relaxing the lint rule. Needs a
  Founder/architecture decision before this mission can be authored as originally conceived, or
  a reinterpretation of "choose the right move" that fits the existing one-deepen-per-layer
  contract (e.g., varying which move is offered across different predicted paths, rather than a
  literal multi-choice hand).

### 1-8 — ランドセル 6年直してまだ同じ？ (Boss)

- **Root type:** しくみ — a genuine identity/continuity puzzle (a repaired randoseru's "sameness"
  over 6 years): material vs. continuity/history/meaning. The capstone topic, appropriately
  abstract.
- **Intended questioning tension:** the classic Ship-of-Theseus structure in a G3-4-accessible,
  concrete form — the child moves from "yes obviously it's the same bag" through noticing how
  much has actually been replaced, toward the deeper question of what makes something "the same
  thing" over time at all.
- **Likely move coverage:** per the old spec table, all four moves across 4 genuine layers — the
  first mission needing real depth-4 (digMachine.ts is already generic over layer count, so no
  engine change is needed for depth alone).
- **Required human gates:** Gate 1, Gate 2 — and given the abstractness, this mission's root
  wording is the highest-risk one to get right register-wise; recommend an early native-speaker
  consult before full authoring, not just at the end.
- **Dependencies — two real blockers, not authoring work:**
  1. Same "player chooses the path" design question as 1-7 (see above) — here doubled, since the
     old spec table describes "player chooses the path" across 4 layers with all 4 moves.
  2. "ふたりミッション: alternate layers" (two people alternating which layer they play) has
     **zero engine implementation** — a repository-wide search for ふたり/two-player/alternating
     co-play found only the spec's own description of it, no code. This is new engine scope, not
     content-authoring, and needs the same Founder/architecture decision as item 1. Until
     resolved, recommend substituting the existing co-play mechanisms (Prediction Battle,
     Teach-back) for 1-8 rather than blocking the whole mission on unbuilt engine work.

## 12 Bank Digs

**A genuine spec/implementation gap, reported rather than papered over:** WO-19 Phase 6 asks to
"prepare all 12 accepted AD-04 Bank topics." No document named AD-04 (or any list of 12 bank
topics) exists anywhere in this repository — searched exhaustively, confirmed absent. The only
bank content ever authored (`ice`) predates the current AD-05 register/AD-01 gap-contract rules
entirely and is `contentClass: "archived"`.

them as "the accepted AD-04 list" would misrepresent unreviewed invention as already-decided
scope — the same category of error these sprints have repeatedly refused to make for claims and
